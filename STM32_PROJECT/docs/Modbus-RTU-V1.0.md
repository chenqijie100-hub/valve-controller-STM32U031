# 机阀驱动板 Modbus RTU 通信协议 V1.0

本协议定义机阀驱动板主站向流量计从站上报数据的接口。流量计端需实现下列项目自定义寄存器。本版用于开发和模拟联调，真实流量计待验收。

## 串口与事务

| 项目 | V1.0 |
| --- | --- |
| 物理接口 | 两线半双工 RS485，主站 USART1 PB6/PB7，PB4 高发送、低接收 |
| 串口 | 19200 bit/s，8 数据位，偶校验，1 停止位 |
| STM32U0 HAL 配置 | 9 位字长加偶校验，有效数据为 8 位 |
| 从站地址 | 0x01，单播 |
| 主站请求 | 0x10，一次写入 0x0100 起连续 7 个保持寄存器 |
| 预留功能 | 0x03 读保持寄存器，0x06 写单个保持寄存器 |
| 响应超时 | 300 ms 测试初值，从主站发送完成起算 |
| 重试 | 最多两次，合计最多三个请求。合法异常应答结束当次上报 |
| 帧间静默 | 19200、8E1 下 t3.5 约 2.006 ms，t1.5 约 0.859 ms |
| 数据顺序 | 寄存器内高字节在前，32 位数据高字在前，CRC 低字节在前 |

RTU 帧为从站地址、功能码、数据字段、CRC16。CRC 初值为 0xFFFF，反射多项式为 0xA001。ASCII 字符 123456789 的 CRC 为 0x4B37。主站在 USART TC 后释放 PB4，随后接收应答。

## 保持寄存器

地址为 PDU 线上的零基地址。V1.0 要求主站可用 0x10 整块写入，支持读回属于后续协商。每个寄存器为无符号 16 位整数。

| 地址 | 字段 | 写入功能码 | 单位或范围 |
| --- | --- | --- | --- |
| 0x0100 | 协议版本 | 0x10 | 固定 1 |
| 0x0101 | 阀门状态 | 0x10 | 0–6，见下表 |
| 0x0102 | 电池电压 | 0x10 | mV，16 位编码范围 0–65535。固件只发送有效 ADC 值 |
| 0x0103 | 故障标志 | 0x10 | 位掩码 |
| 0x0104 | 事件标志 | 0x10 | 位掩码 |
| 0x0105 | 上报序号高字 | 0x10 | 0–65535 |
| 0x0106 | 上报序号低字 | 0x10 | 0–65535 |

| 状态码 | 定义 |
| --- | --- |
| 0 | 位置未知 |
| 1 | 开到位 |
| 2 | 关到位 |
| 3 | 开阀中 |
| 4 | 关阀中 |
| 5 | 中间停止，限位采样有效且两端均未触发 |
| 6 | 异常 |

端位由已确认的状态机输出提供，限位电源关闭时沿用已确认端位。状态变化触发上报，实际发送可能等待安全或正常动作结束，因此报文携带发送前的最新状态。

| Bit | 故障标志 | 事件标志 |
| --- | --- | --- |
| 0 | 断线 | 上电首次状态 |
| 1 | 驱动故障 | 阀门状态变化 |
| 2 | 行程超时 | 断线状态变化 |
| 3 | 双限位异常 | 其他已映射故障状态变化 |
| 4 | 电池低电压 | 周期上报请求 |
| 5 | 通信 9V 保护故障 | 保留 |

故障位采用当前及锁存故障映射。现有阀门固件保留超时位，连续行程超时尚未启用。9V 故障会在之后的可用事务中上报，成功确认后安排恢复上报。电池数据沿用已校准的 ADC 电压快照，低压门槛 6500 mV 是通信试验初值。低压或 ADC 无效时不启动通信。低压事件会保留至恢复供电条件并成功上报。已上电时若电池不再满足条件，立即关断；卸载后电压回升不会单独触发再上电。

事件位在 RAM 中合并。序号按新事件递增，重试使用同一帧和序号。MCU 重启后重新计数。成功应答仅确认发送快照的版本，后续发生的新事件保留待报。从站应允许重复写入同一快照。协议没有独立事务 ID，0x10 正常应答不会回显上报序号。从站应在约定窗口内应答，避免迟到应答跨事务。

## 0x10 示例

下列请求写入版本 1、关到位、电池 7200 mV、无故障、首次状态、序号 1。

```text
请求：01 10 01 00 00 07 0E 00 01 00 02 1C 20 00 00 00 01 00 00 00 01 95 C1
成功：01 10 01 00 00 07 80 37
异常：01 90 02 CD C1
```

正常应答回显首地址 0x0100 和数量 7。异常应答功能码为 0x90，后接一个异常码。常见异常码有 01（非法功能）、02（非法地址）、03（非法数据值）、04（从站设备故障）。主站检查 CRC、地址、功能码、长度和回显。CRC、格式错误及超时受相同的重试上限约束。

## 下一版预留的 9V 通信电源时序

当前板没有 9V 通信电源硬件。默认使用外部已供电的 RS485 设备，PA1、PA4 沿用原 GPIO 初始化，无 9V 上电、FLT# 判断或 500 ms 电源等待。下一版具备硬件后才启用 CMake 选项 `-DVALVE_COMM_9V=ON` 或 CubeIDE 编译宏 `VALVE_COMM_9V_ENABLE=1`。

1. 复位初始化后 PA1 为低，PB4 为接收。阀门安全检查和 ADC 快照先于通信。
2. 有待报事件、阀门控制空闲且电池快照有效并通过通信门槛时，PA1 拉高。启动窗口内忽略 PA4 的暂态。
3. 等待至少 500 ms，检查 PA4 FLT# 为高才允许发送。FLT# 仅用来检测保护信号，现场用示波器另验 9V 和从站准备时间。
4. 满足总线静默后拉高 PB4，至少等待 10 µs，再由 UART 中断发帧。TC 后 PB4 拉低。
5. 在响应窗口内解析完整 RTU 帧。成功、异常、重试耗尽、保护故障或安全抢占时退出，PB4 回接收，PA1 拉低。
6. 活动事务阻止 Stop 1。关断间隔初值为 500 ms，只在有可发送的新事件需要等待时保持运行。9V 电容的实际放电时间需实测。
7. 重试耗尽或保护故障后，待报数据留在 RAM。新的阀门事件或外部周期请求可以发起下一轮。周期请求接口不配置 RTC 唤醒。

## 启用与验收

默认关闭真实写入，保留 115200、8N1 ASCII 配置。隔离台架可用 CMake 的 `-DVALVE_MODBUS=ON -DVALVE_STOP1=ON`。CubeIDE 通过编译器宏 `VALVE_MODBUS_ENABLE=1` 启用；Stop 1 按工程原有 `POWER_LOW_POWER_MODE` 配置。启用时同一 USART 不再解析 ASCII。`.ioc` 保留原有生成基线，重新生成后须核对固件接入点。

当前板用 19200、8E1 的模拟从站接入隔离 RS485 总线，验收回包、重试、断线抢占和 Stop 1，跳过 9V 和 FLT# 测试。先捕获完整 23 字节请求，再按示例规则回 8 字节应答。下一版再用示波器观察 PA1、9V、PA4、PB4 及 UART，核对启动稳定、FLT# 低时禁止发送、末停止位和 DE 下降沿。依次测试正常应答、CRC 错误、静默超时、异常应答、等待应答时断线、动作后恢复上报、关断后回到 Stop 1，并测 9V 残压及待机电流。保护故障可在隔离台架模拟 FLT#，无需短接 9V。

与流量计侧确认地址 0x01、19200/8E1、0x10 整块写入权限及原子更新、全部字段语义和字节序、异常码、重复写入行为，以及通信电源启动和从站应答时限。真实从站接入验收前，保持实际写入开关关闭。
